===============================================================================
CRAZYGAMES SDK INTEGRATION ARCHITECTURE & SPECIFICATION MANUAL
===============================================================================
Target Audience: AI coding agents, developers, and reference implementations.
Purpose: Comprehensive technical specification detailing how to integrate the
CrazyGames HTML5 SDK v3 in plain JavaScript web games, including exact call
signatures, lifecycle hooks, data synchronization, ad rules, and safety patterns.

This specification is based on the Annihilate Earth implementation which includes
several hardened patterns beyond the baseline SDK requirements.

-------------------------------------------------------------------------------
1. ARCHITECTURE OVERVIEW & BRIDGE DESIGN
-------------------------------------------------------------------------------
The codebase abstracts all platform features through a Platform Bridge
(`platform-bridge.js`) that acts as a single adapter between game logic and the
CrazyGames SDK.

Key Architectural Principles:
1. Single Adapter: Game logic calls `window.PlatformBridge.<method>()` unconditionally.
   The bridge handles SDK availability checks internally.
2. Degradation & Fallbacks: If the CrazyGames SDK script fails to load (e.g., adblocker
   or offline), the bridge degrades gracefully to `localStorage` and safe error
   callbacks without throwing runtime exceptions.
3. Eager Initialization & Memoization: `PlatformBridge.init()` fires eagerly when
   `platform-bridge.js` parses and returns a memoized promise so `await init()` in
   `main.js` reuses the same execution context.
4. Intent vs. Reality Separation: `_gameplayActive` tracks what the GAME wants;
   `_sdkGameplayRunning` tracks what the SDK has actually been told. They diverge
   during ads and throttle windows.

Global Namespace Entry: `window.CrazyGames.SDK`

-------------------------------------------------------------------------------
2. LIFECYCLE HOOKS (SDK.game)
-------------------------------------------------------------------------------

A. SDK Initialization
- SDK Call: `await window.CrazyGames.SDK.init()`
- When Used: At boot time in `platform-bridge.js` init(), before preloading assets.
- Behavior: Initializes the SDK runtime, reads initial host settings (e.g. `muteAudio`),
  registers setting listeners, reads SDK locale, and sets up auth change listeners.

B. Loading Events
- SDK Call: `window.CrazyGames.SDK.game.loadingStart()`
  - When Used: Called via `_startLoadingIfNeeded()` after `SDK.init()` completes.
  - Purpose: Signals to CrazyGames that asset downloading/parsing has begun.
  - DEFERRED LOADING PATTERN: If the SDK initializes AFTER `gameLoadingFinished()`
    has already been called, `_startLoadingIfNeeded()` replays both `loadingStart()`
    and `loadingStop()` in the correct order. This ensures events fire properly even
    when the SDK script loads slowly.
- SDK Call: `window.CrazyGames.SDK.game.loadingStop()`
  - When Used: Called via `gameLoadingFinished()` once asset preloading is complete
    and the loader UI begins hiding.
  - Purpose: Signals that the game is fully interactive and playable.

C. First Frame Rendered
- SDK Call: `window.CrazyGames.SDK.firstFrameReady()`
  - When Used: Triggered via `requestAnimationFrame` on the very first canvas paint,
    strictly BEFORE `loadingStop()` / `gameLoadingFinished()`.
  - Purpose: CrazyGames uses this to measure real user-perceived load time. Omitting
    it can hurt your game's QA score on the platform.
  - Implementation: `PlatformBridge.firstFrameReady()` is idempotent (`_firstFrameFired`
    flag) so multiple calls are safe.

D. Gameplay State Tracking (gameplayStart / gameplayStop)
CrazyGames requires strict tracking of active gameplay vs. idle/menu states to
manage ad eligibility and server resources.

THROTTLED SYNC PATTERN:
The SDK throttles `gameplayStart`/`gameplayStop` at 1s per method and SILENTLY
DISCARDS calls inside that window. Simple guard flags are insufficient because a
quick menu toggle (start→stop→start within 1s) leaves the SDK believing gameplay
is stopped.

The solution is a reconciliation layer (`_syncGameplayState()`):
- `_gameplayActive` records the game's INTENT (set by gameplayStart/gameplayStop calls).
- `_sdkGameplayRunning` records what the SDK has actually been TOLD.
- If they diverge and a throttle window would swallow the call, a timer reschedules
  the sync after the throttle expires (`GAMEPLAY_CALL_THROTTLE_MS = 1100`).
- During an ad, intent is overridden to `false` regardless of `_gameplayActive`.

- SDK Call: `window.CrazyGames.SDK.game.gameplayStart()`
  - When Used:
    1. On first player interaction (mousedown/touchstart/pointerdown in `main.js`).
    2. When any overlay/modal popup is closed (via `window.popupClosed(el)` ref-counting).
    3. When an ad break (midgame or rewarded) finishes or fails (via `_resumeAfterAd()`).
    4. When switching to a new planet (`resetGame()` in `planet.js`).

- SDK Call: `window.CrazyGames.SDK.game.gameplayStop()`
  - When Used:
    1. When an overlay/modal popup opens (via `window.popupOpened(el)` ref-counting).
    2. When an ad is about to be requested (via `_pauseForAd()`, BEFORE `requestAd`).
    3. When victory is triggered (`triggerVictory()` in `planet.js`).

Note on Window Focus / Tab Switching:
Per official CrazyGames SDK guidelines, do NOT call `gameplayStop()` in `visibilitychange`
or `blur` event listeners. The CrazyGames SDK automatically detects browser window focus
and tab switches. This implementation correctly avoids this.

E. Celebratory Moments (happyTime)
- SDK Call: `window.CrazyGames.SDK.game.happytime()`
  - When Used: Triggered during positive gameplay moments (e.g. beating the final
    planets: Sun, Neutron Star).

F. Game Completion Percentage
- SDK Call: `window.CrazyGames.SDK.game.reportGameCompletedPercentage(value)`
  - When Used: After planet unlocks and on game load.
  - Value: 0–100 based on planets beaten relative to total planet count.

3. MONETIZATION & ADS (SDK.ad)
-------------------------------------------------------------------------------

- SDK Call: `window.CrazyGames.SDK.ad.requestAd(type, callbacks)`
  - Parameters:
    - `type`: `'midgame'` | `'rewarded'`
    - `callbacks`: `{ adStarted: Function, adFinished: Function, adError: Function }`
  - Trigger Situations:
    1. `'midgame'`: Requested via `showAdBreak()` on planet completion.
    2. `'rewarded'`: Requested via `showRewardedAd()` when player clicks reward buttons.

- CRITICAL MONETIZATION RULES:
  1. `adStarted`: Must suspend audio context and start duration watchdog.
     Gameplay is already stopped BEFORE requestAd (via `_pauseForAd()`).
  2. `adFinished`: Resumes game via `_resumeAfterAd()`. For `'rewarded'`, rewards
     are granted ONLY inside the success callback.
  3. `adError`: Resumes game without granting any reward. An error must NEVER
     result in a reward.
  4. SDK Unavailable Fallback: If `SDK.ad` is missing (e.g. adblocker), the bridge
     settles immediately with `false` (no reward) and never calls the success callback.

- AD WATCHDOG SYSTEM (unique to this implementation):
  Two-tier timeout system prevents permanent game lockup from hung SDK responses:
  1. `AD_REQUEST_TIMEOUT_MS` (10s): If no callback fires within this window after
     `requestAd()`, the ad is treated as failed and the game resumes.
  2. `AD_MAX_DURATION_MS` (120s): If `adStarted` fires but no `adFinished`/`adError`
     follows, the game resumes after this generous timeout.
  Both watchdogs use a single `settle()` function that runs exactly once per ad
  request, ensuring no caller is ever left waiting on a callback that never arrives.

- AD TRANSITION OVERLAY (unique to this implementation):
  A CSS-animated skewed overlay (`_runTransitionIn` / `_runTransitionOut`) covers the
  screen during ad load/unload. This hides visual jank from the SDK injecting/removing
  ad iframes. The transition blocks input during its animation via `pointer-events: all`.

- AD PENDING FLAGS:
  `_adRequestPending` is set synchronously before the ad request so that
  `popupClosed()` ref-counting does not briefly emit `gameplayStart()` right before
  the ad's `_pauseForAd()` calls `gameplayStop()`. `_adInProgress` is the stronger
  flag set by `_pauseForAd()` that forces intent to `false` in `_syncGameplayState()`.

- INPUT RELEASE BEFORE AD:
  `_pauseForAd()` calls `window.releaseHeldInput()` to drop any in-progress hold
  (e.g. laser beam, lightning charge) that would never see its release event due to
  input being frozen during the ad.

- DUPLICATE REQUEST GUARD:
  Both `showAdBreak()` and `showRewardedAd()` check `_adInProgress || _adRequestPending`
  and bail with the appropriate callback (onComplete for midgame, onFailed for rewarded)
  to prevent overlapping ad requests.

- LOCAL DEV MOCK:
  When running on localhost and the SDK is unavailable, rewarded ads auto-grant success
  so reward flows can be tested without a live SDK connection.

4. DUAL-PERSISTENCE & CLOUD SAVE MIRRORING (SDK.data)
-------------------------------------------------------------------------------

- SDK Calls:
  - `window.CrazyGames.SDK.data.setItem(key, value)`
  - `window.CrazyGames.SDK.data.getItem(key)`
  - `window.CrazyGames.SDK.data.removeItem(key)`

- DUAL-WRITE MIRROR PATTERN:
  CrazyGames `SDK.data` performs cloud-synced storage for logged-in users. However, if a
  player later plays offline or with an adblocker, `SDK.data` will be unavailable.

  To prevent data loss (`safeLocalStorage` in `system.js`):
  1. `setItem(key, val)` ALWAYS writes to `localStorage` synchronously FIRST, then
     attempts to write to `SDK.data.setItem(...)`. SDK.data debounces writes by ~1s
     (up to 30s in edge cases), so the local mirror is what survives tab teardown.
  2. `getItem(key)` reads from `SDK.data` first. If cloud returns non-null, it wins.
     If cloud returns null, falls back to localStorage (which may contain a more
     recent write that SDK.data's debounce dropped).
  3. A `getLocalItem(key)` method reads the local mirror only, bypassing SDK.data,
     for reconciling saves the SDK's debounce may have lost.

- SAVE CACHE & MIGRATION:
  The parsed save is held in memory (`_saveCache`) and treated as authoritative for the
  session, avoiding repeated SDK.data reads during boot. `readGameState()` compares
  timestamps between cloud and local copies, preferring whichever is newer.
  Save migrations run stepwise from the save's `_version` to `SAVE_VERSION`.

- AUTH CHANGE INVALIDATION (unique to this implementation):
  `_setupAuthListener()` watches for CrazyGames login/logout events. When auth changes,
  the in-memory save cache is invalidated via `invalidateGameStateCache()`, forcing the
  next read to go back to storage. This prevents a stale cached save from overwriting
  the newly synced cloud data.

- DIRTY-CHECK OPTIMIZATION:
  `saveGameState()` serializes the state (minus `_savedAt` timestamp) and compares it to
  `_persistedJson`. If nothing changed, the write is skipped entirely.

5. AUDIO SYNCHRONIZATION (SDK.game.settings)
-------------------------------------------------------------------------------

- SDK Calls:
  - `window.CrazyGames.SDK.game.settings.muteAudio`
  - `window.CrazyGames.SDK.game.addSettingsChangeListener(cb)`

- Implementation Rules:
  1. The platform's mute state OVERRIDES in-game volume settings.
  2. `_setupSettingsListener()` listens to `addSettingsChangeListener` and calls
     `soundManager.setCrazyGamesMuted(settings.muteAudio)`.
  3. Muting is implemented at the Web Audio Master Gain Node level. Player stored
     volume preferences are NEVER zeroed out (preserving cloud save settings).
  4. Mute is re-applied at `gameLoadingFinished()` in case `soundManager` was created
     after settings were first read.

- POST-AD MUTE SAFETY NET (unique to this implementation):
  `_resumeAfterAd()` calls `_reapplyMuteState()` which re-reads the SDK's current
  `muteAudio` flag and pushes it to the audio system. This prevents audio leaking
  when the platform mute was toggled during an ad and the settings listener was
  no-oped or missed.

- AUDIO SUSPEND/RESUME FOR ADS:
  Audio context is suspended only in `_suspendAudioForAd()` (called from `adStarted`),
  not when the ad is merely requested. This avoids silencing the game during the seconds
  an unfilled request takes to fail. Resume only happens if this bridge actually
  suspended the context (`_audioSuspendedForAd` flag), and only if `!document.hidden`.

6. USER IDENTITY & LOCALE (SDK.user)
-------------------------------------------------------------------------------

- SDK Calls:
  - `window.CrazyGames.SDK.user.systemInfo.locale`
    - Returns: BCP-47 locale string (e.g. `"en-US"`, `"zh-CN"`).
    - Read during init via `_readLocale()` and exposed via `getLocale()`.
    - Used as primary language detection for first-time visitors before falling
      back to `navigator.language`. Saved language preferences take precedence
      on return visits.
  - `window.CrazyGames.SDK.user.addAuthListener(cb)`
    - Used to detect login/logout and invalidate save cache (see §4).

-------------------------------------------------------------------------------
7. POPUP & MODAL TRACKING SYSTEM (openPopupCount)
-------------------------------------------------------------------------------

To maintain strict `gameplayStart`/`gameplayStop` balance across nested UI elements:
- Global counter: `openPopupCount` (in `state.js`).
- Element marking: `el.__popupCounted = true` ensures an overlay closed via multiple
  inputs (e.g., Escape key AND click) cannot decrement the counter twice.
- Flow:
  - `openPopupCount` transitions 0 -> 1: calls `PlatformBridge.gameplayStop()`
    (guarded by `gameplayStarted && !victoryTriggered`).
  - `openPopupCount` transitions 1 -> 0: calls `PlatformBridge.gameplayStart()`
    (guarded by `gameplayStarted && !victoryTriggered && !gamePausedForAd`).
- `window.popupOpened(el)` and `window.popupClosed(el)` are the public API.
- `window.resetPopupCount()` force-clears the counter and all element markings,
  used when all popups are dismissed at once (e.g. hard game reset).
- Tracked popups: options overlay, ad-spin overlay. The victory screen uses direct
  `gameplayStop()` (it's a terminal state, not a dismissible popup).

-------------------------------------------------------------------------------
8. SITELOCK & AUTHORIZATION
-------------------------------------------------------------------------------

`PlatformBridge.isAuthorizedHost()` determines whether the game is running on an
authorized host:
1. If the SDK initialized successfully (`sdkReady`), the host is authorized. A
   rehosted copy cannot make CrazyGames' SDK initialize for it.
2. If on localhost/127.0.0.1, authorized (local development).
3. Hostname regex fallback for `crazygames.*` domains, so an adblocker that blocks
   the SDK script on the genuine site doesn't lock a paying player out.

Victory is gated behind `isAuthorizedHost()` in `triggerVictory()`.
